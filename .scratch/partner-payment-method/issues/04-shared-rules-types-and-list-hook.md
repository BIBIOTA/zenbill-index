# 04 — shared package：型別、顯示規則、清單 hook

**What to build:** Web 與 App 共用同一份「這個欄位何時出現、標籤該寫什麼、清單從哪來」的規則，於是兩端的行為不可能不一致。

這張票交付的是**行為規則本身**，不含任何畫面。它是 05 與 06 的地基，做在這裡就不會在兩個 repo 各寫一次、也不會各錯一次。

顯示條件刻意**不做任何以人名為基礎的身分判定**：欄位是否出現取決於「這個帳本有沒有提供清單」這項能力，與 partner 是誰無關。標籤文字則相反 —— 顯示的是使用者認得的人名。

**Blocked by:** 01, 03

**Status:** ready-for-agent

- [x] 共用型別中的共同支出加上選填的 partner 付款方式欄位，與 01 的 API 契約一致
- [x] 新增純函式判定「這筆共同支出是否顯示付款方式欄位」：清單非空 **且** partner 實付金額大於零
- [x] 兩人都出錢的支出會顯示（判定依據是 partner 實付金額，不是誰是主要付款人）
- [x] partner 未出錢時不顯示，即使清單非空
- [x] 清單為空或讀取失敗時不顯示
- [x] 新增純函式產生欄位標籤文字，取該帳本 partner 的顯示名，並在無別名、無 partner 名稱時退回預設值
- [x] 新增取得付款方式清單的 hook，呼叫 03 的端點，並讓呼叫端能分辨「載入中」「成功」「失敗」
